# NS16 与机器狗对接

板子 `eth0` 接入机器狗网络 `192.168.1.0/24`。机器狗侧地址保持原配置。板侧地址已保存。按下列顺序接线并登录。

## 1. 机器狗地址

| 设备 | 地址 |
| --- | --- |
| 运动主机 | `192.168.1.103` |
| 感知主机 | `192.168.1.105` |
| 记录主机 | `192.168.1.106` |
| 其他设备 | `192.168.1.1`、`192.168.1.10`、`192.168.1.11` |

记录主机的用户名为 `ysc`，主机名为 `ysc-perception`。

## 2. 板侧参数

| 项目 | 取值 |
| --- | --- |
| 接口 | `eth0` |
| 地址 | `192.168.1.110/24` |
| 默认网关 | `192.168.1.106` |
| DNS | `223.5.5.5` |

`eth0` 只有这一个地址。默认路由的下一跳是记录主机 `192.168.1.106`。该主机把来自 `192.168.1.110` 的流量从自己的外部网卡送出。不再使用 `192.168.88.0/24`。

## 3. 接线

网线一端接入板子 `eth0`（RJ45），另一端接入机器狗网口。

## 4. 从机器狗网络登录

操作电脑接入机器狗 Wi-Fi 后执行。机器狗内的主机直接执行下列命令。

```sh
ping -c 3 192.168.1.110
ssh nvidia@192.168.1.110
```

应收到应答。首次连接提示主机密钥时输入 `yes`。

| 项目 | 取值 |
| --- | --- |
| 用户名 | `nvidia` |
| 密码 | `nvidia` |
| `sudo` 密码 | `nvidia` |

登录后主机名为 `ubuntu`。

主机密钥与已知记录不一致时，在发起连接的主机上执行：

```sh
ssh-keygen -R 192.168.1.110
ssh nvidia@192.168.1.110
```

ECDSA 指纹为 `SHA256:WgOsBiCTREUrUwPE4pxxbW4pnG2vXKlXEDRcv1fILfk`。

## 5. 操作电脑经网线直连

网线一端接入板子 `eth0`，另一端接入操作电脑的以太网口。经 USB 以太网适配器接入时，使用插上后新出现的那块网卡。只改这一块网卡。

该网卡的 IPv4 选择手动，按下表填写后保存。路由器留空。操作电脑原有的上网接口与默认路由保持不变。

| 项目 | 取值 |
| --- | --- |
| IP 地址 | `192.168.1.20` |
| 子网掩码 | `255.255.255.0` |
| 路由器 | 留空 |

不要使用 `192.168.1.1`、`.10`、`.11`、`.103`、`.105`、`.106`、`.110`、`.111`。不要启用互联网共享。

保存后执行：

```sh
ping -c 3 192.168.1.110
ssh nvidia@192.168.1.110
```

应收到应答。登录账号与第 4 节相同。这根网线只用于登录。板子上网仍走第 2 节的网关 `192.168.1.106`，需要 `eth0` 接在机器狗上。
